# 로드맵 생성 로직

## 개요
사용자가 목표를 입력하고 레벨 테스트를 거쳐 학습 기간을 선택하면 최종적으로 개인화된 로드맵이 생성되는 전체 흐름을 설명합니다.

---

## 전체 흐름

```
RoadmapGenerate → LevelTest → DurationSelect → RoadmapView
```

---

## 1. RoadmapGenerate (목표 입력)

### 경로
- `/` (루트 경로)

### 주요 기능
사용자가 달성하고 싶은 목표를 입력하는 첫 번째 단계입니다.

### 프로세스

1. **목표 입력**
   - 사용자가 텍스트 입력 필드에 목표를 입력 (예: "풀스택 개발자가 되고 싶어요")
   - Enter 키 또는 제출 버튼으로 제출

2. **API 요청**
   - **Endpoint**: `POST /api/goals`
   - **Request Body**:
     ```json
     {
       "goal": "사용자가 입력한 목표"
     }
     ```

3. **응답 처리**
   - **Response**:
     ```json
     {
       "surveyId": "생성된 설문 ID",
       "questions": [
         {
           "id": 1,
           "question": "질문 내용",
           "options": ["옵션1", "옵션2", "옵션3", "옵션4"]
         }
       ]
     }
     ```

4. **페이지 이동**
   - LevelTest 페이지로 이동하면서 `surveyId`와 `questions` 데이터를 state로 전달
   - `navigate('/level-test', { state: { surveyId, questions } })`

### 상태 관리
- 로컬 상태로 `goal`, `isLoading` 관리
- 로딩 중에는 "목표를 분석하고 있습니다..." 메시지 표시

---

## 2. LevelTest (기초 진단)

### 경로
- `/level-test`

### 주요 기능
사용자의 현재 수준을 파악하기 위한 설문 조사를 진행합니다.

### 프로세스

1. **데이터 수신 및 검증**
   - 이전 페이지에서 전달받은 `surveyId`와 `questions` 확인
   - 데이터가 없으면 루트 페이지로 리다이렉트
   - `surveyId`를 전역 상태(Zustand store)에 저장

2. **설문 진행**
   - 질문을 하나씩 표시 (현재 진행률 표시)
   - 사용자가 각 질문에 대한 답변 선택
   - "다음" 버튼으로 다음 질문으로 이동
   - "돌아가기" 버튼으로 이전 질문으로 이동

3. **답변 수집**
   - 각 질문의 답변을 로컬 상태에 저장
   - 형식: `{ [questionId]: "선택한 답변" }`

4. **설문 제출**
   - 마지막 질문에서 "제출" 버튼 클릭
   - **Endpoint**: `POST /api/surveys/{surveyId}`
   - **Request Body**:
     ```json
     {
       "answers": [
         {
           "questionId": 1,
           "answer": "선택한 답변"
         }
       ]
     }
     ```

5. **페이지 이동**
   - 설문 제출 성공 후 DurationSelect 페이지로 이동
   - `navigate('/duration-select')`

### 상태 관리
- **로컬 상태**: `currentQuestionIndex`, `answers`, `isSubmitting`
- **전역 상태**: `surveyId` (Zustand store에 저장)

### UI 특징
- 진행률 바로 현재 진행 상황 표시
- 질문 번호 표시 (예: 1/5)
- 답변 선택 시 시각적 피드백

## 3. DurationSelect (학습 기간 설정)

### 경로
- `/duration-select`

### 주요 기능
사용자가 로드맵 학습 기간을 선택합니다.

### 프로세스

1. **surveyId 확인**
   - 전역 상태에서 `surveyId` 가져오기
   - 없으면 루트 페이지로 리다이렉트

2. **기간 옵션 제공**
   - **AI 추천**: AI가 최적의 학습 기간 설정
   - **8주**: 빠른 집중 학습
   - **12주**: 안정적인 속도
   - **16주**: 여유로운 학습

3. **기간 선택**
   - 사용자가 원하는 기간 옵션 선택
   - 선택된 옵션 시각적으로 강조

4. **로드맵 생성 요청**
   - **Endpoint**: `POST /api/roadmaps`
   - **Request Body**:
     ```json
     {
       "surveyId": "저장된 설문 ID",
       "duration": "8" | "12" | "16" | "auto"
     }
     ```

5. **응답 처리**
   - **Response**:
     ```json
     {
       "roadmapId": "생성된 로드맵 ID"
     }
     ```

6. **페이지 이동**
   - 로드맵 생성 성공 후 로드맵 상세 페이지로 이동
   - `navigate(/roadmap/${roadmapId})`
   - 또는 roadmapId가 없으면 로드맵 목록 페이지로 이동 (`/roadmap`)

7. **상태 정리**
   - 사용된 `surveyId`를 전역 상태에서 제거 (`clearSurveyId()`)

### 상태 관리
- **로컬 상태**: `selectedDuration`, `isLoading`
- **전역 상태**: `surveyId` (읽기 및 삭제)

### UI 특징
- 각 기간 옵션에 대한 설명 제공
- 라디오 버튼 스타일의 선택 UI
- "나중에 변경할 수 있습니다" 안내 메시지

---

## API 엔드포인트 요약

| 단계 | 메서드 | 엔드포인트 | 설명 |
|------|--------|-----------|------|
| 1 | POST | `/api/goals` | 목표 입력 및 설문 생성 |
| 2 | POST | `/api/surveys/{surveyId}` | 설문 답변 제출 |
| 3 | POST | `/api/roadmaps` | 로드맵 생성 |
| 4 | GET | `/api/roadmaps/{roadmapId}` | 로드맵 조회 |

---

## 데이터 흐름

```
1. 사용자 목표 입력
   ↓
2. 서버에서 surveyId + questions 생성
   ↓
3. surveyId를 전역 상태에 저장
   ↓
4. 사용자가 설문 답변
   ↓
5. 답변을 surveyId와 함께 서버에 제출
   ↓
6. 사용자가 학습 기간 선택
   ↓
7. surveyId + duration으로 로드맵 생성 요청
   ↓
8. roadmapId + roadmapData 반환
   ↓
9. 기존 로드맵 데이터 삭제 후 새 데이터 저장
   ↓
10. surveyId 전역 상태에서 제거
   ↓
11. RoadmapView 페이지로 이동
   ↓
12. 저장된 로드맵 데이터 표시
```

## 4. RoadmapView (로드맵 상세 보기)

### 경로
- `/roadmap/:id`

### 주요 기능
생성된 로드맵을 시각적으로 표시하고 주차별 학습 계획을 확인할 수 있습니다.

### 프로세스

1. **로드맵 ID 확인**
   - URL 파라미터에서 `roadmapId` 추출
   - ID가 없으면 루트 페이지로 리다이렉트

2. **로드맵 데이터 확인**
   - 전역 상태(Zustand store)에 저장된 로드맵 데이터 확인
   - 같은 ID의 데이터가 있으면 API 호출 생략
   - 없거나 다른 ID면 API 호출

3. **로드맵 조회 API**
   - **Endpoint**: `GET /api/roadmaps/{roadmapId}`
   - **Response**:
     ```json
     {
       "roadmapId": "로드맵 ID",
       "title": "로드맵 제목",
       "weeks": [
         {
           "week": 1,
           "title": "주차 제목",
           "description": "주차 설명",
           "days": [
             {
               "day": 1,
               "title": "일일 학습 내용"
             }
           ]
         }
       ]
     }
     ```

4. **데이터 저장**
   - 기존 로드맵 데이터 삭제 (`clearRoadmap()`)
   - 새로운 로드맵 데이터 저장 (`setRoadmap(id, data)`)

5. **UI 렌더링**
   - 주차별 카드 형태로 로드맵 표시
   - 각 주차의 일일 학습 계획 표시
   - 진행률 및 통계 정보 표시

### 상태 관리
- **로컬 상태**: `isLoading`, `currentWeek`
- **전역 상태**: `roadmapId`, `roadmapData` (Zustand store)

### UI 특징
- 가로 스크롤 형태의 주차별 카드 레이아웃
- 진행 단계 표시 (5단계)
- 현재 주차, 총 일수, 진행률 통계
- 각 주차별 일일 학습 계획 표시

## 5. 전역 상태 관리 (Zustand Stores)

### surveyStore
설문 ID를 페이지 간에 공유하기 위한 전역 상태 관리

```typescript
interface SurveyStore {
  surveyId: string | null;
  setSurveyId: (id: string) => void;
  clearSurveyId: () => void;
}
```

### roadmapStore
로드맵 데이터를 저장하고 관리하기 위한 전역 상태 관리

```typescript
interface RoadmapStore {
  roadmapId: string | null;
  roadmapData: RoadmapData | null;
  setRoadmap: (id: string, data: RoadmapData) => void;
  clearRoadmap: () => void;
}
```

### 특징
- 두 store 모두 `persist` 미들웨어 사용
- 브라우저 새로고침 시에도 데이터 유지
- localStorage에 각각 'survey-storage', 'roadmap-storage' 키로 저장

### 사용 시점
**surveyStore**:
- **저장**: LevelTest 페이지 진입 시
- **읽기**: DurationSelect 페이지에서 로드맵 생성 시
- **삭제**: 로드맵 생성 완료 후

**roadmapStore**:
- **저장**: DurationSelect에서 로드맵 생성 성공 시
- **읽기**: RoadmapView 페이지에서 로드맵 표시 시
- **삭제**: 새로운 로드맵 생성 시 (기존 데이터 제거)
